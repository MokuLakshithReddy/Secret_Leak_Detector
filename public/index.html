Methodological Caution & Transparent Analysis of 78% Real-World Recall

Methodological Disclaimers: A 100-file curated corpus is essential empirical evidence, but it is not enough to establish broad real-world superiority over mature tools across millions of heterogeneous production repositories. Rather than suppressing or overfitting regexes to artificially inflate the 78% score back to 100%, we report the exact failure modes transparently:

1. DB Connection URI With Special Chars (Postgres & Mongo)
Passwords containing unescaped '@' symbols (e.g. P@ssw0rd998877!) cause regex lookaheads expecting user:password@host to split prematurely on the inner '@'.
postgres://admin:P@ssw0rd!@prod-db.aws.com:5432/db
2. Unquoted Azure Connection String Parameters
In C# / .NET appsettings.json, AccountKey=... is embedded inside a compound semicolon-separated string without quotation marks around the key name itself.
DefaultEndpointsProtocol=https;AccountKey=FQbmx8...==;...
3. Controlled vs Real-World Generalization
Controlled 1,000-fixture datasets validate canonical API key structures (AWS, Stripe, GitHub PAT). Real-world codebases introduce compound configs, non-standard URL encodings, and legacy templates.
Recall: 100% (Controlled) vs 78.0% (Real-World)
